# Задача 3. K-th

## 1. Объяснение решения

Задача — найти `k`-й по величине элемент массива без сортировки и без куч. Используется **quickselect** — алгоритм,
основанный на той же идее, что quicksort, но с одним ключевым отличием: после разбиения рекурсия идёт **только в ту
часть**, где лежит искомый элемент, а не в обе.

### Переход к «k-му наименьшему»

`k`-й по величине — это то же, что `(n − k)`-й по возрастанию (0-индексированный). Пример: `[3, 2, 1, 5, 6, 4]`,
`k = 2`, `n = 6`, `target = 4`. В отсортированном `[1, 2, 3, 4, 5, 6]` элемент с индексом 4 — это `5`. Совпадает с
ответом.

Так удобнее, потому что разбиение в quickselect традиционно формулируется через индексы в порядке возрастания, и
`target` — это просто позиция, куда мы «целимся».

```python
n = len(nums)
if not 1 <= k <= n:
    raise ValueError(...)
target = n - k
```

### Итеративный quickselect с трёхпутевым разбиением

Каждая итерация:

1. Выбираем pivot случайно из текущего диапазона `[lo, hi)`.
2. Разбиваем диапазон на три зоны: `< pivot | == pivot | > pivot`. Возвращаем `(lt, gt)` — границы средней зоны.
3. Смотрим, куда попал `target`:
    - `target < lt` — искомый элемент в левой части, сужаем `hi = lt`.
    - `target >= gt` — искомый в правой части, сужаем `lo = gt`.
    - иначе `target ∈ [lt, gt)` — все элементы в этой зоне равны `pivot`, значит ответ — `pivot`.

```python
lo, hi = 0, n
while hi - lo > 1:
    pivot = arr[rng.randint(lo, hi - 1)]
    lt, gt = _partition_3way(arr, lo, hi, pivot)
    if target < lt:
        hi = lt
    elif target >= gt:
        lo = gt
    else:
        return pivot
return arr[lo]
```

### Почему трёхпутевое, а не классическое (Lomuto)

Классический quickselect через Lomuto-разбиение ставит pivot в известную позицию `p` и рекурсирует в `[lo, p)` или
`[p+1, hi)`. На **массиве с дубликатами** это ломается: если все элементы равны `pivot`, Lomuto отделяет ровно один
элемент (сам pivot), и диапазон уменьшается на 1 за итерацию. Сложность вырождается в:

$$n + (n-1) + (n-2) + \dots = O(n^2)$$

Трёхпутевое разбиение ловит **все** равные `pivot` в среднюю зону. Если `target` попал в неё — ответ найден сразу, за
одну итерацию. На массиве из одинаковых элементов — `O(n)` на **одну** партицию, дальше зоны `<` и `>` пусты, работа
завершена.

Именно поэтому во втором примере из условия — `[3, 2, 3, 1, 2, 4, 5, 5, 6]`, `k = 4` — трёхпутевое разбиение заметно
выигрывает: дубликатов там много.

### Разбиение

```python
def _partition_3way(arr, lo, hi, pivot):
    lt = i = lo
    gt = hi
    while i < gt:
        if arr[i] < pivot:
            arr[lt], arr[i] = arr[i], arr[lt]
            lt += 1
            i += 1
        elif arr[i] > pivot:
            gt -= 1
            arr[i], arr[gt] = arr[gt], arr[i]
        else:
            i += 1
    return lt, gt
```

Три индекса делят диапазон на четыре зоны:

```
lo          lt          i           gt          hi
│ < pivot   │ == pivot  │  неизвестно │ > pivot   │
```

- `arr[i] < pivot` — расширяем левую зону, меняем `arr[lt]` и `arr[i]`, оба индекса сдвигаются вправо. `i` можно
  двигать, потому что новый `arr[i]` (бывший `arr[lt]`) уже проверен — он был `== pivot` или совпадал с `i`.
- `arr[i] > pivot` — расширяем правую зону, уменьшаем `gt`, меняем `arr[i]` и `arr[gt]`. **`i` не двигаем** — новый
  `arr[i]` пришёл из непроверенной зоны.
- `arr[i] == pivot` — просто `i += 1`.

Когда `i >= gt`, все «неизвестные» обработаны. Возвращаем `(lt, gt)`.

### Почему random pivot

При детерминированном выборе pivot (например, `arr[lo]`) существует вход, на котором алгоритм вырождается в `O(n²)`.
Классический пример — **отсортированный массив**: pivot = минимум, зона `<` пустая, диапазон уменьшается на 1. Random
pivot делает этот сценарий вероятностно невозможным: ожидаемое время — `O(n)` для **любого** фиксированного входа.

### Мутация

`arr = nums.copy()` в начале. Quickselect работает in-place, но пользователю важно, что исходный массив не меняется.
Если нужна «настоящая» in-place семантика — уберите копию, но тогда `main` модифицирует `nums`.

### Завершение цикла

`while hi - lo > 1`. Выход из цикла возможен в двух случаях:

1. Сработал `return pivot` в ветке `else`. Это нормальный выход — ответ найден.
2. `hi - lo == 1`. Остался ровно один элемент, и `target` указывает именно на него (по построению: мы сужали диапазон
   вокруг `target`, а `target` — валидный индекс). Возвращаем `arr[lo]`.

Второй случай — это когда pivot случайно отделил всё кроме одного элемента. Например, `target = 0`, pivot = второй
минимум, `lt = 1`, `gt = 1 + count(== pivot)`. Тогда `target < lt`, `hi = 1`, `lo = 0`, `hi - lo = 1`, выходим из цикла,
`arr[0]` — минимум, он же ответ.

## 2. Оценка сложности

### Время

**Среднее: `Θ(n)`.**

Ключевое отличие от quicksort: после разбиения рекурсия идёт **только в одну часть**, а не в обе. Стоимость партиции на
уровне — `O(n)`, и дальше обрабатывается часть размером примерно `n/2`. Ряд:

$$n + \frac{n}{2} + \frac{n}{4} + \dots = 2n = O(n)$$

Множитель 2 — константа. Это и есть главный выигрыш quickselect над quicksort: не `O(n log n)`, а `O(n)` в среднем.

**Худшее: `O(n²)`.**

Возможно, если pivot **каждый раз** оказывается крайним элементом, и `target` при этом лежит в большой части. Ряд
`n + (n−1) + (n−2) + … = O(n²)`. С random pivot вероятность такого сценария — `O((2/n)^k)` для `k` итераций, что
астрономически мало для больших `n`. Для любого фиксированного входа **ожидаемое** время `O(n)`.

**Дубликаты: `O(n)`.**

Трёхпутевое разбиение на массиве из одинаковых элементов делает **одну** партицию за `O(n)` и сразу возвращает `pivot` (
потому что `target` попадает в зону `[lt, gt)`). Если дубликатов много, но не все — сложность `O(n log k)`, где `k` —
число уникальных значений, но на практике всё ближе к `O(n)`.

**Отсортированный / обратно отсортированный: `O(n)` в среднем, `O(n²)` в худшем.**

Без random pivot было бы `O(n²)` детерминированно. С random — ожидаемое `O(n)`. Худший случай возможен, но вероятность
исчезающе мала.

### Память

**`O(1)` дополнительной памяти.**

- `arr = nums.copy()` — `O(n)` на копию, чтобы не мутировать вход. Если убрать копию — `O(1)`.
- В цикле — только локальные переменные `pivot, lt, gt, lo, hi, i` — `O(1)`.
- **Никакой рекурсии** — итеративная версия, стек вызовов не используется вообще. Это ключевое отличие от рекурсивного
  quickselect, где глубина стека могла быть `O(log n)` в среднем и `O(n)` в худшем.

Итого: `O(n)` на копию входа (или `O(1)`, если мутировать `nums` разрешено). Стек — константный.

### Сравнение с альтернативами

| Подход                  | Время (среднее) | Время (худшее) | Память | Комментарий              |
|-------------------------|-----------------|----------------|--------|--------------------------|
| Сортировка              | `O(n log n)`    | `O(n log n)`   | `O(n)` | запрещено условием       |
| Куча (`heapq`)          | `O(n log k)`    | `O(n log k)`   | `O(k)` | запрещено условием       |
| Quickselect (2-way)     | `O(n)`          | `O(n²)`        | `O(1)` | `O(n²)` на дубликатах    |
| **Quickselect (3-way)** | **`O(n)`**      | `O(n²)`        | `O(1)` | **`O(n)` на дубликатах** |

## 3. Визуализация работы алгоритма

### Пример 1: `nums = [3, 2, 1, 5, 6, 4]`, `k = 2`

`n = 6`, `target = 6 − 2 = 4`. Ищем элемент, который в отсортированном массиве стоял бы на позиции 4 (0-индексация).
Ожидаемый ответ — `5`.

**Итерация 1.** `lo = 0, hi = 6`. Скажем, pivot = `4` (случайно попался такой элемент).

Партиция:

```
[3, 2, 1, 5, 6, 4]  pivot = 4
      ↓
[3, 2, 1 | 4 | 5, 6]
 ← < 4 →   ==    > 4
```

`lt = 3, gt = 4`. `target = 4`. Проверяем:

- `target < lt` → `4 < 3` — нет.
- `target >= gt` → `4 >= 4` — да. Идём вправо: `lo = 4`.

**Итерация 2.** `lo = 4, hi = 6`. Диапазон `[5, 6]`. Скажем, pivot = `5`.

```
[..., 5, 6]  pivot = 5
      ↓
[..., | 5 | 6]
         ==   >
```

`lt = 4, gt = 5`. `target = 4`. Проверяем:

- `target < lt` → `4 < 4` — нет.
- `target >= gt` → `4 >= 5` — нет.
- Иначе: `target ∈ [4, 5)` → **возвращаем `pivot = 5`**.

Ответ: `5`. ✓

### Пример 2: `nums = [3, 2, 3, 1, 2, 4, 5, 5, 6]`, `k = 4`

`n = 9`, `target = 9 − 4 = 5`. Ожидаемый ответ — `4`.

**Итерация 1.** `lo = 0, hi = 9`. Скажем, pivot = `3`.

```
[3, 2, 3, 1, 2, 4, 5, 5, 6]  pivot = 3
              ↓
[1, 2, 2 | 3, 3 | 4, 5, 5, 6]
 ← < 3 →   == 3    > 3
```

`lt = 3, gt = 5`. `target = 5`. Проверяем:

- `target < lt` → `5 < 3` — нет.
- `target >= gt` → `5 >= 5` — да. Идём вправо: `lo = 5`.

**Итерация 2.** `lo = 5, hi = 9`. Диапазон `[4, 5, 5, 6]`. Скажем, pivot = `5`.

```
[4, 5, 5, 6]  pivot = 5
      ↓
[4 | 5, 5 | 6]
<5   == 5   >5
```

`lt = 6, gt = 8`. `target = 5`. Проверяем:

- `target < lt` → `5 < 6` — **да**. Идём влево: `hi = 6`.

**Итерация 3.** `lo = 5, hi = 6`. Диапазон `[4]`. `hi − lo = 1` → выходим из цикла. Возвращаем `arr[5]`.

Что было в `arr[5]` после двух партиций? Партиция 1 поставила `4` на позицию 5 (первый элемент зоны `> 3`). Партиция 2
поставила `4` на позицию 5 (первый элемент зоны `< 5`). Итог — `arr[5] = 4`. ✓

### Трёхпутевое разбиение по шагам

Возьмём фрагмент `[3, 2, 3, 1, 2]` из первого примера, `lo = 0, hi = 5`, pivot = `3`.

```
Начало: lt=0, i=0, gt=5
[3, 2, 3, 1, 2]
 ↑
 lt,i,gt

i=0, a[0]=3 == 3 → i=1
[3, 2, 3, 1, 2]
 ↑  ↑
 lt i

i=1, a[1]=2 < 3 → swap a[0],a[1], lt=1, i=2
[2, 3, 3, 1, 2]
    ↑  ↑
    lt i

i=2, a[2]=3 == 3 → i=3
[2, 3, 3, 1, 2]
    ↑     ↑
    lt    i

i=3, a[3]=1 < 3 → swap a[1],a[3], lt=2, i=4
[2, 1, 3, 3, 2]
       ↑  ↑
       lt i

i=4, a[4]=2 < 3 → swap a[2],a[4], lt=3, i=5
[2, 1, 2, 3, 3]
          ↑
          lt,i,gt

i >= gt → стоп. return (3, 5)

Результат:
[2, 1, 2 | 3, 3]
 ← < 3 →   == 3
```

Зона `== 3` содержит два элемента. Если бы `target` был 3 или 4, мы бы вернули `3` сразу, без следующих итераций.

### Рекурсивное дерево в quicksort vs цепочка в quickselect

Для контраста — как выглядело бы то же разбиение в **quicksort**:

```
              [все 6 элементов]
              /                \
       [левая часть]       [правая часть]
        /        \           /        \
      ...       ...         ...       ...
```

`n!`-подобная структура, `O(n log n)` работы.

В **quickselect** — только один путь:

```
[все 6 элементов] → partition
    ↓ target в правой части
[правая часть] → partition
    ↓ target в средней зоне
    return pivot
```

Одна ветка, `O(n) + O(n/2) + ... = O(n)`.

### Почему трёхпутевое разбиение важно на дубликатах

Возьмём `[7, 7, 7, 7, 7]`, `target = 2` (средний).

**С Lomuto** (2-way):

- pivot = 7, все элементы равны pivot.
- Lomuto ставит pivot в `p = lo = 0`, левая зона `< 7` пустая, правая — `n − 1 = 4`.
- `target = 2 > 0`, идём вправо, диапазон `[1, 5)`.
- Снова pivot = 7, снова `p = 1`, диапазон `[2, 5)`.
- Снова `p = 2`, `target == 2` → нашли `arr[2] = 7`.

5 шагов, каждый — `O(n)` партиция → `O(n²)` в общем случае.

**С трёхпутевым** (3-way):

- pivot = 7. Все элементы попадают в зону `== 7`: `lt = 0, gt = 5`.
- `target = 2 ∈ [0, 5)` → **возвращаем `pivot = 7` сразу**.

1 шаг, `O(n)` партиция → `O(n)` в общем случае. Ровно это и есть главное достоинство трёхпутевого разбиения в
quickselect.
