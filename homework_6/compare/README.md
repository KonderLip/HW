# Задача 1. Compare

## 1. Объяснение решения

В задаче три части: декоратор `timed` для замера времени, две рекурсивные сортировки и их сравнение.

### Декоратор `timed`

Декоратор принимает функцию и возвращает обёртку, которая замеряет её время через `time.perf_counter()` — монотонные
часы с высоким разрешением, не подверженные скачкам системного времени.

Три детали, которые важны:

- **`try/finally`** — время записывается даже при исключении. Для сортировки это не критично, но это привычка: если
  функция упадёт, замер всё равно останется в `records`, и в отладке будет видно, сколько времени прошло до падения.
- **`functools.wraps`** — копирует `__name__`, `__doc__`, `__wrapped__`. Без него `mergesort.__name__` стал бы
  `"wrapper"`, и тесты, которые проверяют имя функции, упали бы.
- **`records` в замыкании** — список замеров доступен через `wrapper.records` (не через глобальную переменную). У
  каждого декорированного объекта свой `records`, они не пересекаются.

`timed` — фабрика обёрток. `timed(mergesort)` создаёт **новую** обёртку каждый раз, со своим `records`. Это позволяет
замерять одну и ту же функцию в разных местах независимо.

### Mergesort

Сортировка слиянием — это «разделяй и властвуй»: делим массив пополам, сортируем каждую половину рекурсивно, сливаем два
отсортированных массива в один.

```python
def _msort(arr, buf, lo, hi):
    if hi - lo <= 1:
        return
    mid = (lo + hi) // 2
    _msort(arr, buf, lo, mid)
    _msort(arr, buf, mid, hi)
    if arr[mid - 1] <= arr[mid]:
        return
    _merge(arr, buf, lo, mid, hi)
```

**Ключевые решения:**

**Общий буфер `buf`.** Наивный mergesort на каждом слиянии создаёт новый список — суммарно `O(n log n)` памяти вместо
`O(n)`. Здесь `buf` создаётся один раз в `mergesort` и передаётся вниз по рекурсии. Слияние пишет результат в
`buf[lo:hi]`, затем копирует обратно в `arr[lo:hi]`. Так на весь алгоритм нужен ровно один массив размера `n`.

**Проверка `arr[mid-1] <= arr[mid]`.** Если последний элемент левой половины не больше первого элемента правой — отрезок
уже отсортирован. На **отсортированном** входе это условие выполняется на **каждом** уровне рекурсии, и `_merge` никогда
не вызывается. Время падает с `O(n log n)` до `O(n)`. На случайных данных проверка почти всегда ложна, поэтому цена —
одно сравнение на узел, что пренебрежимо мало.

**Стабильность.** При слиянии `arr[i] <= arr[j]` (не `<`) означает, что при равных ключах левый элемент идёт первым. Это
сохраняет исходный порядок равных элементов — mergesort **стабилен**.

### Quicksort

Быстрая сортировка — тоже «разделяй и властвуй», но работа делается **до** рекурсии: выбираем опорный элемент (pivot),
переставляем элементы так, что все меньшие идут слева, большие — справа, и рекурсивно сортируем обе части.

```python
def _partition(a, lo, hi, rng):
    pivot = a[rng.randint(lo, hi - 1)]
    i = lo - 1
    j = hi
    while True:
        i += 1
        while a[i] < pivot:
            i += 1
        j -= 1
        while a[j] > pivot:
            j -= 1
        if i >= j:
            return j
        a[i], a[j] = a[j], a[i]
```

**Ключевые решения:**

**Hoare partition, а не Lomuto.** Классическое разбиение Ломуто ставит pivot в конец и делает один проход слева направо,
отправляя все элементы `≥ pivot` вправо. На массиве с дубликатами (например, все элементы равны) это даёт `O(n²)`: pivot
отделяет только один элемент за раз. Hoare использует два указателя с концов и **разносит равные элементы в обе стороны
**, поэтому массив из одинаковых сортируется за `O(n log n)`.

**Random pivot.** `a[rng.randint(lo, hi − 1)]` выбирает pivot случайно. Это критично: при детерминированном выборе (
например, `a[lo]` или `a[(lo+hi)//2]`) существует **killer-последовательность** — специально сконструированный вход, на
котором алгоритм деградирует до `O(n²)`. Теорема McIlroy (1999) доказывает, что для любого детерминированного выбора
pivot такой вход можно построить. Рандомизация делает этот сценарий вероятностно невозможным.

**Без swap на место `a[lo]`.** В отличие от Lomuto, Hoare работает со **значением** pivot, а не с его позицией.
`pivot` — это просто переменная, равная какому-то элементу массива. После разбиения pivot может оказаться где угодно:
слева, справа, в середине. Функция возвращает `j` — границу между «≤ pivot» и «≥ pivot», а не позицию самого pivot. Это
экономит один swap на каждый вызов `_partition`.

**Граница `p+1` в рекурсии.** `_qsort(a, lo, p + 1)` и `_qsort(a, p + 1, hi)`. Обратите внимание на `+1` в первом
вызове: `a[p]` уже стоит на своём месте, повторно его обрабатывать не нужно. `p = hi − 1` невозможен, потому что `j`
начинается с `hi` и уменьшается хотя бы раз, значит правая часть всегда содержит хотя бы один элемент и обе рекурсивные
ветви строго короче исходного отрезка.

## 2. Оценка сложности

### Mergesort

**Время:**

- Рекурсивное деление — `O(log n)` уровней.
- На каждом уровне слияние всех отрезков вместе — `O(n)`.
- Итого: `O(n log n)` в **худшем**, **среднем** и **лучшем** случае.

С проверкой `arr[mid-1] <= arr[mid]`:

- **Отсортированный вход:** условие выполняется на каждом уровне, `_merge` не вызывается → `O(n)`.
- **Обратно отсортированный:** условие ложно на каждом уровне → `O(n log n)`.
- **Случайный:** `O(n log n)`.

**Дополнительная память:** `O(n)` — один буфер `buffer` длины `n`, живёт всё время работы. Стек рекурсии — `O(log n)`.

**Стабильность:** да.

### Quicksort

**Время:**

- Средний случай: `O(n log n)` — при random pivot ожидаемое количество сравнений ≈ `2n ln n ≈ 1.39 n log₂ n`.
- Худший случай: `O(n²)` — возможен, но при random pivot вероятность падает экспоненциально с `n`. Для любого *
  *фиксированного** входа ожидаемое время `O(n log n)`.
- На массиве с **дубликатами:** `O(n log n)` благодаря Hoare. На массиве из одинаковых элементов — `O(n log n)`, а не
  `O(n²)`.

**Дополнительная память:** `O(log n)` в среднем — стек рекурсии глубиной `O(log n)`. В худшем случае `O(n)`, но с random
pivot ожидаемая глубина `O(log n)`. **In-place**: никаких вспомогательных массивов, сортировка на копии `arr` (копия в
`quicksort` — для того, чтобы не мутировать вход).

**Стабильность:** нет. Swap'ы с концов перемешивают равные элементы.

### Сравнение

| Свойство             | Mergesort                  | Quicksort                  |
|----------------------|----------------------------|----------------------------|
| Время (среднее)      | `O(n log n)`               | `O(n log n)`               |
| Время (худшее)       | `O(n log n)`               | `O(n²)`, но вероятность ~0 |
| Память               | `O(n)`                     | `O(log n)`                 |
| Стабильность         | ✓                          | ✗                          |
| Отсортированный вход | **`O(n)`** (short-circuit) | `O(n log n)`               |
| Дубликаты            | `O(n log n)`               | `O(n log n)`               |

**Когда что выбирать:** mergesort — если нужна стабильность или входные данные часто отсортированы. Quicksort — если
важна память (`O(log n)` vs `O(n)`) или данные случайны. На практике в Python `sorted()` использует Timsort — гибрид
mergesort и insertion sort, который выигрывает у обоих на реальных данных.

## 3. Визуализация работы алгоритма

### Mergesort: деление и слияние

Возьмём `[5, 2, 8, 1, 9, 3, 7, 4]`.

**Фаза деления** (идёт сверху вниз):

```
[5, 2, 8, 1, 9, 3, 7, 4]
        /           \
[5, 2, 8, 1]     [9, 3, 7, 4]
    /    \          /    \
[5, 2] [8, 1]   [9, 3] [7, 4]
 /  \   /  \     /  \   /  \
[5][2] [8][1]   [9][3] [7][4]
```

**Фаза слияния** (идёт снизу вверх, каждая строка — результат):

```
[2, 5]  [1, 8]     [3, 9]  [4, 7]
    \      /           \      /
   [1, 2, 5, 8]     [3, 4, 7, 9]
           \           /
      [1, 2, 3, 4, 5, 7, 8, 9]
```

**Как работает `_merge` на паре `[2, 5]` и `[1, 8]`:**

| Шаг | `i` | `j` | `arr[i]` | `arr[j]` |             Сравнение              | `buf[k]` |
|:---:|:---:|:---:|:--------:|:--------:|:----------------------------------:|:--------:|
|  1  |  0  |  2  |    2     |    1     |            `2 > 1` → j             |    1     |
|  2  |  0  |  3  |    2     |    8     |            `2 ≤ 8` → i             |    2     |
|  3  |  1  |  3  |    5     |    8     |            `5 ≤ 8` → i             |    5     |
|  4  |  2  |  3  |    —     |    8     | левая кончилась → копируем остаток |    8     |

`buf[lo:hi]` = `[1, 2, 5, 8]`, копируется обратно в `arr[lo:hi]`.

**Short-circuit в действии.** Если на входе уже `[1, 2, 3, 4, 5, 6, 7, 8]`, то на верхнем уровне
`arr[3] = 4 <= arr[4] = 5` — условие выполнено, `_merge` **не вызывается**. Рекурсия спускается до размеров 1, на каждом
уровне проверяет одно условие и сразу возвращается. Итого `n − 1` сравнений вместо `O(n log n)` работы по слиянию.

### Quicksort: разбиение и рекурсия

Возьмём `[5, 2, 8, 1, 9, 3, 7, 4]`, pivot = 5 (для наглядности; в коде — случайный).

**Один шаг `_partition(a, 0, 8, rng)` с pivot = 5:**

Начальное состояние: `i = -1`, `j = 8`.

| Шаг | Действие                                                                                                                     | `i` | `j` | Массив                     |
|:---:|------------------------------------------------------------------------------------------------------------------------------|:---:|:---:|----------------------------|
|  1  | `i++` до 0, `a[0] = 5 ≥ 5` → стоп. `j--` до 7, `a[7] = 4 ≤ 5` → стоп                                                         |  0  |  7  | `[5, 2, 8, 1, 9, 3, 7, 4]` |
|  2  | `i < j` → swap(`a[0]`, `a[7]`)                                                                                               |  0  |  7  | `[4, 2, 8, 1, 9, 3, 7, 5]` |
|  3  | `i++` до 1, `a[1] = 2 < 5`, `i++` до 2, `a[2] = 8 ≥ 5` → стоп. `j--` до 6, `a[6] = 7 > 5`, `j--` до 5, `a[5] = 3 ≤ 5` → стоп |  2  |  5  | `[4, 2, 8, 1, 9, 3, 7, 5]` |
|  4  | `i < j` → swap(`a[2]`, `a[5]`)                                                                                               |  2  |  5  | `[4, 2, 3, 1, 9, 8, 7, 5]` |
|  5  | `i++` до 3, `a[3] = 1 < 5`, `i++` до 4, `a[4] = 9 ≥ 5` → стоп. `j--` до 4, `a[4] = 9 > 5`, `j--` до 3, `a[3] = 1 ≤ 5` → стоп |  4  |  3  | `[4, 2, 3, 1, 9, 8, 7, 5]` |
|  6  | `i = 4 ≥ j = 3` → return `j = 3`                                                                                             |  4  |  3  | —                          |

**Результат разбиения:** `a[0..3] ≤ 5` и `a[4..7] ≥ 5`:

```
[4, 2, 3, 1 | 9, 8, 7, 5]
 ← ≤ 5 →    ← ≥ 5 →
```

Позиция `p = 3`. Рекурсия идёт по `[0, 4)` и `[4, 8)`. **Сам pivot (5) нигде не «припаркован»** — он оказался в правой
части на позиции 7 и продолжит участвовать в рекурсии. Это и есть ключевое отличие Hoare от Lomuto: pivot — значение, а
не позиция.

**Рекурсивное дерево** (pivot'ы выбраны для наглядности):

```
              [5, 2, 8, 1, 9, 3, 7, 4], pivot=5
                        /          \
            [4, 2, 3, 1]            [9, 8, 7, 5]
            pivot=2                 pivot=8
            /       \                /      \
         [1, 2]   [4, 3]          [7, 5]   [9]
         p=0      p=0             p=0
         /  \     /  \            /  \
       [1] [2]   [3] [4]         [5] [7]   [9]
```

Глубина дерева — `O(log n)` при хорошем балансе. С random pivot ожидаемая глубина `O(log n)` для любого входа.

### Почему random pivot важен

С `pivot = a[lo]` на **отсортированном** массиве `[1, 2, 3, 4, 5, 6, 7, 8]`:

```
pivot = 1 → разбиение: [1] и [2, 3, 4, 5, 6, 7, 8]
pivot = 2 → разбиение: [2] и [3, 4, 5, 6, 7, 8]
pivot = 3 → разбиение: [3] и [4, 5, 6, 7, 8]
...
```

Каждый раз отрезается **один** элемент. Дерево рекурсии вырождается в линию глубины `n`, сложность `O(n²)`. С random
pivot на том же входе pivot с вероятностью `1/n` окажется крайним, а с вероятностью `~1/2` — в средней трети массива.
Ожидаемая глубина `O(log n)`.
