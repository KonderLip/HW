# Задача 3. Balanced Binary Tree

## 1. Объяснение решения

Дерево сбалансировано по высоте, если для **каждого** узла высоты левого и правого поддеревьев отличаются не более чем
на 1. Высота пустого дерева — 0, листа — 1.

Наивная проверка «сравнить высоты в корне» не работает: корень может быть сбалансирован, а несбалансированность прячется
глубже. Поэтому нужно проверить **все** узлы. Естественный способ — обойти дерево в порядке **post-order** (DFS):
сначала обработать детей, потом родителя. Тогда к моменту обработки узла высоты обоих его поддеревьев уже известны.

Рекурсивный вариант выглядит так:

```python
def dfs(node):
    if node is None:
        return 0
    hl = dfs(node.left)
    hr = dfs(node.right)
    if abs(hl - hr) > 1:
        raise Unbalanced
    return max(hl, hr) + 1
```

Рекурсию можно развернуть в явный стек. Каждый узел попадает в стек **дважды**: сначала как `(node, False)` — «зашли
впервые, надо развернуть детей», потом как `(node, True)` — «дети уже обработаны, можно считать высоту». Между этими
двумя моментами в отдельный стек `h` складываются высоты завершённых поддеревьев. Когда обрабатывается `(node, True)`,
из `h` снимаются две последние высоты — это `h(right)` и `h(left)` (именно в таком порядке, потому что правый ребёнок
кладётся в стек раньше левого и, следовательно, завершается позже). Проверяем разницу, кладём `max + 1` обратно в `h`.

## 2. Оценка сложности

**Время: `O(n)`**, где `n` — число узлов.

- Каждый реальный узел кладётся в стек дважды — `(node, False)` и `(node, True)` — и дважды снимается.
- Каждый `None`-ребёнок кладётся один раз как `(None, False)`. Таких рёбер `n + 1` (у `n` узлов всего `2n` рёбер, из них
  `n − 1` ведут к реальным узлам).
- Итого `O(n)` записей в стеке, каждая обрабатывается за `O(1)`.
- Аналогично `h`: `2n + 1` операций `append`/`pop`, каждая `O(1)`.

**Дополнительная память: `O(h)`**, где `h` — высота дерева.

- Стек вызовов в любой момент содержит не более `O(h)` записей: это путь от корня к текущему узлу плюс отложенные правые
  поддеревья.
- Стек `h` в любой момент хранит высоты завершённых поддеревьев, ожидающих родителя; их число тоже ограничено глубиной,
  `O(h)`.

В худшем случае (дерево-линия) `h = n`, поэтому память `O(n)`. В лучшем (полное дерево) `h = log n`, память `O(log n)`.

## 3. Визуализация работы алгоритма

### Сбалансированное дерево

Возьмём дерево из четырёх узлов:

```
        1
       / \
      2   3
     /
    4
```

Post-order обход: `4 → 2 → 3 → 1`. Рядом с каждым узлом — вычисленная высота:

```
                       1  (h = max(2,1)+1 = 3)
                      / \
   (h=max(1,0)+1=2)  2   3  (h = max(0,0)+1 = 1)
                    /
                   4  (h = max(0,0)+1 = 1)
```

Проверки разницы: узел `4` — `|0−0| = 0`; узел `2` — `|1−0| = 1`; узел `3` — `|0−0| = 0`; узел `1` — `|2−1| = 1`. Везде
`≤ 1` → `True`.

### Тот же пример через явный стек

`F` = `(node, False)`, `T` = `(node, True)`, `N` = `(None, False)`. В колонке «stack» верхушка — **справа**. `h` — стек
высот.

|  # |   pop   | действие                          | stack после                     | h после     |
|---:|:-------:|-----------------------------------|---------------------------------|-------------|
|  1 | `(1,F)` | push `(1,T)`, `(3,F)`, `(2,F)`    | `(1,T) (3,F) (2,F)`             | `[]`        |
|  2 | `(2,F)` | push `(2,T)`, `(N,F)`, `(4,F)`    | `(1,T) (3,F) (2,T) (N,F) (4,F)` | `[]`        |
|  3 | `(4,F)` | push `(4,T)`, `(N,F)`, `(N,F)`    | `… (4,T) (N,F) (N,F)`           | `[]`        |
|  4 | `(N,F)` | `h.append(0)`                     | `… (4,T) (N,F)`                 | `[0]`       |
|  5 | `(N,F)` | `h.append(0)`                     | `… (4,T)`                       | `[0, 0]`    |
|  6 | `(4,T)` | `right=0, left=0`, `h.append(1)`  | `…`                             | `[1]`       |
|  7 | `(N,F)` | правый ребёнок `2`, `h.append(0)` | `… (2,T) (N,F)`                 | `[1, 0]`    |
|  8 | `(2,T)` | `right=0, left=1`, `h.append(2)`  | `(1,T) (3,F)`                   | `[2]`       |
|  9 | `(3,F)` | push `(3,T)`, `(N,F)`, `(N,F)`    | `(1,T) (3,T) (N,F) (N,F)`       | `[2]`       |
| 10 | `(N,F)` | `h.append(0)`                     | `… (N,F)`                       | `[2, 0]`    |
| 11 | `(N,F)` | `h.append(0)`                     | `(1,T) (3,T)`                   | `[2, 0, 0]` |
| 12 | `(3,T)` | `right=0, left=0`, `h.append(1)`  | `(1,T)`                         | `[2, 1]`    |
| 13 | `(1,T)` | `right=1, left=2`, `h.append(3)`  | `[]`                            | `[3]`       |

На шагах 8 и 13 порядок важен: `h.pop()` сначала возвращает **правую** высоту, потом **левую**. Это следствие того, что
при развороте узла мы пушим сначала `(node, True)`, потом правого ребёнка, потом левого — LIFO гарантирует, что левый
завершится первым, а его высота окажется в `h` ниже правой.

### Несбалансированное дерево

```
        1
       / \
      2   3
     /
    4
   /
  5
```

Post-order: `5 → 4 → 2 → 3 → 1`. Высоты: `h(5)=1`, `h(4)=2`, `h(2)=max(2,0)+1=3`, но ещё на шаге узла `2`:

```
h(4) = 2,  h(None) = 0  →  |2 − 0| = 2 > 1  →  return False
```

До узлов `1` и `3` алгоритм даже не доходит — ранний выход. Это и есть тот случай, который не ловится проверкой только в
корне: у корня `1` левое поддерево имело бы высоту 3, правое — 1, разница тоже 2, но проверка в узле `2` срабатывает
раньше и дешевле.

### Почему нужен `visited`

Без флага `visited` узел обрабатывался бы как «первый заход» бесконечно: мы бы снова и снова пушили его детей, не
понимая, что они уже посчитаны. Флаг превращает запись `(node, False)` в `(node, True)` ровно один раз — после того, как
оба ребёнка завершились и их высоты легли в `h`. Это стандартный приём разворота рекурсии с post-order обходом.
